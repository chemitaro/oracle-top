最初に知っておく用語

セッション
Oracleが一回の実行について保存した記録です。同じChatGPT会話へ続けて送っても、別のOracleセッションになることがあります。
スロット／lease
Oracleがブラウザ使用枠を確保したときの台帳記録です。セッション件数と同じとは限りません。
推論レベル／effort
Oracleが保存した推論の指定値です。実際のChatGPT画面や利用枠を証明する値ではありません。
ローリング期間
今から24時間前、または7日前までです。「今日の0時から」ではありません。
Snapshot
一回の読み取りで作る共通データです。画面・テキスト・JSONはこれを使って表示します。

成功率と送信回数は、別々の数字です

成功率は、Oracleが結果を保存できたセッションの割合です。送信回数は、その後失敗しても送信操作に到達した分を含みます。

成功率 = completed ÷ (completed + partial + error)
例：24 ÷ (24 + 2 + 4) = 80.0%

cancelledは件数を表示しますが、成功率の分母には含めません。評価対象が0件なら、0%ではなくN/Aを表示します。成功率と同じ内容を反対から示す失敗率は表示しません。

送信回数は、保存されたpromptSubmittedがtrueなら初回を1件として数えます。ユーザーターンを確認するhashがなくても数えます。同じ実行内の追加送信は、初回の送信記録がtrueで、実行が完了し、予定配列の全要素が有効な場合だけその件数も加えます。途中で失敗した場合は初回の1件だけです。

この回数は、ChatGPTアカウントの正確な利用数や残量ではありません。直接ChatGPTを使った分は含みません。送信時刻がないため開始時刻で代替し、途中の追加送信は少なく数える場合があります。Oracleが古い履歴を削除すると、7日間の数字も少なくなります。

読めない場合、画面に収まらない場合

      
壊れたJSONが一件あっても、読めるセッションは表示します。警告により、集計が欠けている可能性を伝えます。セッション保存先全体を読めないときは、現在一覧・信頼性・送信表をN/Aにします。台帳が壊れている場合もN/Aです。初回から台帳がない場合は、警告付きの保存0件として扱います。

      
幅が狭い場合はプロジェクト名とタスク名を先に短縮します。重要な列さえ収まらない場合は、端末を広げるかsnapshotを使うように案内します。高さが足りない場合は、省略した行数を表示します。JSONと単発テキストでは全件を確認できます。

      
終了するときは、カーソルやキー入力の設定を元に戻します。Oracleファイルを修復したり、残ったスロットを削除したりする処理はありません。

    

    

      
使い方と設定

      
Node.js 24を用意し、ソースのディレクトリで次を実行します。配布tarballから導入する手順はREADMEにも記載しています。

      
npm ci
npm run build
node dist/cli.js
node dist/cli.js snapshot --json

      
パッケージの導入後は、次の短いコマンドを使えます。

      
oracle-top
oracle-top --interval 2s
oracle-top snapshot
oracle-top snapshot --json

      
TUIはqまたはCtrl-Cで終了します。画面の切り替え、詳細ログ、通知は作りません。パイプやファイルへの出力にはsnapshotを使います。

      
セッションの保存先とブラウザのプロファイルは別の設定です。ORACLE_HOME_DIRだけを変えても、既定のブラウザプロファイルは移りません。観測する一つのプロファイルを選び、その台帳を読みます。

      
このツールが表示するrunningは、Oracleの保存値です。日時が不明または未来なら経過時間をN/Aにします。実際のChatGPTで回答が終わっていても、Oracleがrunningのままならそのまま表示します。
